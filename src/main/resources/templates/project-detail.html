Locator ranking (Android)

Android projects use a fixed tier list. Picking a mode is not available here — this table is the authoritative order the binder walks.

RankTierExampleWhy it's ranked here
0 USER_OVERRIDE anything you pinned on Add a locator manually Explicit human intent wins over everything else.
1 RESOURCE_ID AppiumBy.id("com.app:id/signin") Survives copy changes and translations. Preferred first.
2 ACCESSIBILITY AppiumBy.accessibilityId("login_submit") Compiler-friendly, screen-reader-stable. Common for custom views.
3 LABEL_SIBLING xpath walking a labelled sibling node For un-ided controls that have a labelled neighbour.
4 TEXT_CLASS androidUIAutomator new UiSelector().text(…) Visible text + class. Brittle across translations — avoided when a higher tier matches.
5 XPATH relative xpath only Last resort. Absolute xpath is banned.

CSS is never valid in NATIVE_APP context and will fail at bind time. See MOBILE_FRAMEWORK_RULES for the full discipline.

Authoring engine

"Auto" lets Cursor pick the cheapest-good model per call (recommended). Pin a specific model only when this project keeps mis-binding on complex pages (then choose a stronger model) or when runs are too expensive (choose a cheaper one).

When enabled, Precision tries proven locators saved from past Keel or Precision runs on this host before calling Cursor. When off, every bind uses Cursor (or Keel fallback) as today.

Leave blank to use the server default (50).

Cursor selects targets first. If unavailable, unsuccessful, or at the call limit, Keel takes over and the run reports the fallback reason. DOM validation and browser execution still apply.

Precision is disabled on this server — jobs will use Keel.

AI validation

Cursor reviews what Keel produces (TC coverage, framework repair after a bad build, failure investigation after a red run, Bug Hunter triage). On for every project. A project you had turned off is turned back on once. After that, saving this panel off stays off. When on, each AI task is charged at the AI validation price the account owner sets on Admin → Prices. If you turn it off, every workflow still runs — it just skips the AI layer and uses deterministic checks only.
