  • TC_ID — unique per row (e.g. TC_01)
  • Title — short case name
  • Steps — numbered user actions (exact UI labels)
  • ExpectedResult — observable outcomes (prefer one per step)
  • Preconditions — login need, role, starting context
  • Priority / Tags — e.g. P1, smoke,login
  • VisualAssertion — optional text describing how the screen should look after steps pass (not an image; Figma/mockup PNGs are uploaded separately on the project for Execute)
  • TestData — optional values, line-aligned with Steps (aliases: Test Data, StepData)
02

Login & credentials

Say when auth is needed in Preconditions. Put shared secrets in run config.

Needs auth

Preconditions

Write Login required. or User must be logged in as …

One case only

In that row

Case-specific user/password (or role) may live in Preconditions or Steps.

Many cases

Run config

Leave Excel empty of secrets. Enter Username / Password once on Upload.

Public pages

Preconditions: No login required. — do not force auth.

Negative login

Keep wrong-user / wrong-password steps in Steps. Put the exact error text in ExpectedResult.

03

Writing steps

One clear action per line. Name the control and the action from the live UI.

Avoid

Vague shorthand

  1. Login
  2. Add item
  3. Check
Prefer

Exact actions

  1. Open the Login Page at /login
  2. Enter the username
  3. Enter the password
  4. Click the Login button
  5. Confirm the text Secure Area is visible
  • Use visible labels: button text, field label, menu item, message copy.
  • Include navigation when needed: Open the … page at /path.
  • Confirmations: Confirm the text … is visible.
  • Do not embed dummy names like Test / User in Enter lines — use TestData.
04

Expected results

One overall result works; per-step expected results are better for automation fidelity.

Steps

1. Click the Remove button
2. Confirm the text It's gone is visible

ExpectedResult

1. Remove starts and the checkbox disappears
2. Message "It's gone" is shown on the page
  • Align numbering with Steps (1. … 2. … or After step 4: …).
  • Quote exact UI text for messages, headings, and toasts.

Avoid

Literals in the step

  1. Enter Test in the First name field
  2. Enter User in the Surname field

Test / User / foo / fname are never typed as real data.

Prefer

Field in Steps · value in TestData

  1. Enter in the First name field
  2. Enter in the Surname field

TestData lines: Nora then Bennett. Leave a cell blank to invent a realistic value.

  • Line 1 of TestData pairs with step 1, even if that step is only Open / Confirm.
  • Dropdown picks may stay in the step (Select 15 from the Day dropdown) or sit in TestData.
  • Blank TestData (or blank line) → Keel invents from the field identity (names, *@example.com, etc.).
06

Visual assertion

Optional. Describes what the screen should look like after the case’s DOM steps pass.

  • Write a short claim in plain language (form visible, heading present, cart still shown).
  • DOM steps remain the source of truth for pass/fail of actions.
  • Uncertain or very low-confidence visual answers alone do not fail a case that already passed its steps.
07

What each case must include

Everything the converter needs to design the automated case — no guessing.

Context

Starting page, role, and whether login is required.

Exact actions

Named controls and verbs — not “do the thing”.

Distinct names

When two similar items exist, name both so nothing is swapped.

Observable outcomes

What the user should see or reach after each important step.

08

Not supported yet

Leave these out of the workbook for now.

File upload flows

Choose file, attach document, and drag-and-drop upload are not supported. Do not include TCs whose only purpose is uploading. Cover the rest of the flow without upload steps.

09

AI rewrite → CSV

Copy a ready prompt into any AI chat. The AI returns CSV (not .xlsx) with Keel headers — then open in Excel and import via Automate.

  1. Click Copy prompt.
  2. Paste into any AI chat (ChatGPT, Claude, Cursor, etc.).
  3. Paste one batch of rough TCs (about 5–15, or one feature/tag).
  4. Copy the AI's CSV only into Excel (or save as .xlsx).
  5. Spot-check a few rows, then open Automate to upload.

Large suites: repeat per batch and append rows in Excel. Do not paste the whole workbook at once.
